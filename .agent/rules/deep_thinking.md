# Principle of Deep Thinking
1. **Analyze Before Acting**: Deconstruct requests into atomic steps. Ask: " Does this solution actually solve the users root problem?\
2. **Explore Alternatives**: List at least 2 solutions for complex architectural problems. Compare them based on safety and maintainability.
3. **Trace Dependencies**: Before modifying a function, list all its callers. Ensure the change is compatible with existing usage.
4. **Self-Correction**: If a tool fails or a plan hits a snag, pause and re-evaluate. Do not blindly retry the same action.
